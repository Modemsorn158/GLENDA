# Study provenance and reproducibility limits

The records below identify **representative rewritten repository snapshots with matching recorded source-file hashes**. Commit IDs changed when dataset images were removed from main history on 21 November 2026; a local old-to-new mapping was retained during the rewrite. These snapshots are not proof of the exact Git commit used for training, a clean working tree, every transitive dependency, the original data custodian's identity, or the complete execution environment at run time. When comparing Git blobs with the recorded Windows files, both LF and CRLF line endings were considered. The original run did not record a complete Git/environment attestation, so one cannot be reconstructed retrospectively.

The [artifact manifest](../reports/artifact_manifest.json) records the original study's selected input, source and artifact hashes. The extended study's [protocol](../reports/deep_development_protocol.md) and [results](../reports/deep_development_results.md) describe its configuration and results. The recorded GPU package versions are in `requirements-gpu.lock`. This file has version pins but no package hashes; it does not prove the identity of installed wheels or guarantee deterministic GPU execution. The current checkout does not distribute the local study's predictions, weights or ledger. Dataset images were removed from reachable main history, but old clones or caches may retain them. See the [image-handling guidance](data_privacy.md).

Later source changes intentionally require stronger grouping, content, output-ledger and inference checks for future runs. Historical candidate selections and checkpoints do not acquire those guarantees retroactively, and the newer final-fit code must not be used to silently mix them with changed training code. Historical checkpoints require explicit legacy acknowledgement in the demo. The old holdout is already consumed and must not be evaluated again for model or threshold selection.
