# Response to the external project review

## Assessment

The review's main conclusion is consistent with the recorded results: the current model is a research artifact and its holdout performance does not establish reliable clinical detection or patient-level generalization. The high accuracy should not be read in isolation. An always-negative classifier would achieve 2,688/2,763 = 97.29% accuracy and zero sensitivity on this holdout. The selected model detected 20 of 75 annotated positive **frames**, not 20 of 75 independent patients or cases. It missed 55 positive frames across 20 known linked groups; unknown patient relationships prevent conversion to an independent-patient count.

The review correctly identifies the near-one threshold, wide variation in out-of-fold score scales, score calibration problems, source confounding, limited negative groups, short training budget and direct aspect-ratio-distorting resize. It also correctly notes that unit tests and a holdout ledger do not establish scientific validity. The current source-specific negative data are particularly limited: only three known linked groups contribute negative holdout frames, and one contributes 84.4% of them. The empirical bootstrap's zero-width intervals at the observed zero-false-positive operating point do not establish perfect specificity or precision on unseen groups.

Some qualifications matter. A threshold close to one, by itself, does not prove the cause of the model's errors. The Brier score combines calibration, discrimination and outcome uncertainty; it is not a pure calibration measure. The held-out reliability plot and very high Brier score together indicate substantial calibration problems in this evaluated sample, but they do not establish the mechanism. Differences in fold score distributions can reflect both model behavior and the different cases in each fold. The holdout results are consistent with threshold-transfer problems, but they do not prove that threshold transfer caused low sensitivity. No causal claim about surgical instruments, illumination or other possible shortcuts follows solely from these data.

## Changes made in response

- The demo reports a neutral above- or below-threshold model result and explicitly states that a negative result does not rule out pathology. It remains local and research-only.
- Each demo session uses a separate temporary upload directory and attempts cleanup when Python exits normally or unwinds after a handled exception. An abrupt termination left a directory in an actual synthetic test, so cleanup and secure erasure are not guaranteed. See the README for inspection and retention guidance, including the existing legacy `gradio_tmp` directory.
- The [development-only threshold-transfer diagnostic](../reports/threshold_stability.md) chooses an F1 threshold from four saved development folds and applies it to the fifth. Fold-level recall ranges from 0.1017 to 0.8500 in this exploratory analysis. Model selection used all five folds, and the models producing the other-fold scores were trained on the target fold. This is not a nested or independent estimate and it does not measure transfer to the final refit. It does not change the trained model, the selected threshold or the consumed holdout.
- The [holdout table](../reports/test_results.md) explicitly includes the always-negative accuracy reference. The report now clarifies that the Brier score alone does not isolate calibration.

## Priority work that remains

1. Obtain authoritative case mappings for the 15 negative video IDs without known case identifiers and an independently collected, appropriately governed external cohort with substantially more independent negative cases. A new model or threshold needs a fresh independent evaluation cohort; this already-consumed holdout cannot be reused as an unbiased test for revisions.
2. Prespecify an operating requirement with qualified domain experts, including the intended use and the sensitivity, specificity and uncertainty tradeoffs. Evaluate calibration and threshold selection on data separated by verified patient or source groups from model fitting, and use a further independent group-separated evaluation. If using out-of-fold predictions, evaluate the complete selection, calibration and refit procedure with an appropriately nested design; pooling scores from different models alone does not validate their transfer to a refitted model.
3. Investigate potential source shortcuts using matched acquisition or sampling where available, source-aware and patient-aware evaluation, and carefully controlled sensitivity analyses. Any explanation or mask-overlap analysis remains distinct from proving clinical causality or lesion localization.
4. On development data only, compare aspect-ratio-preserving preprocessing and relevant input sizes with the current direct resize, and run targeted one-factor ablations, longer convergence checks and repeated seeds within a documented compute budget. Do not select changes using the consumed holdout.
5. Preserve privacy-safe provenance, dependency versions and synthetic tests, and improve independent artifact availability where the dataset terms permit. Package hashes, checkpoint redistribution, epoch-level resumption, reliable patient metadata and truly external validation remain unresolved. A temporary upload directory and localhost binding do not constitute a complete medical-data retention or security policy.

For calibration methods and their limits, see Guo et al., *On Calibration of Modern Neural Networks* (2017), https://proceedings.mlr.press/v70/guo17a.html, and the scikit-learn probability-calibration documentation, https://scikit-learn.org/stable/modules/calibration.html. Neither source establishes that post-hoc calibration will work for this dataset or replaces an independent calibration cohort.
