# Response to the November 2026 repository audit

The audit reviewed public source and reports without executing the private study. Its research conclusions remain important: the original model missed 55 of 75 positive holdout frames, patient independence is unknown, three known groups supplied the negative holdout frames, and no external validation has been performed. These changes do not improve those historical results or authorize reusing the consumed holdout.

**Historical finding and subsequent action:** At the time of this audit response, an ancestor contained dataset images in public Git history. On 21 November 2026 the owner authorized a history rewrite to remove the dataset-image paths from reachable main history. Earlier clones or caches may still contain the files; rewriting history does not guarantee erasure. The owner and data custodian should review prior access, repository visibility and the dataset's terms. Repository visibility was not changed.

## Addressed in the current code

- **Known grouping and trusted inputs (GL-12, GL-14):** training and evaluation entry points require a trusted inventory and candidate-pair file with independently recorded hashes. The verifier checks complete manifest coverage, labels, canonical connected groups and partition/fold separation, including shared case, video, exact image hash and candidate links, before reading the relevant image bytes. The explicitly named `_synthetic_test_only` library option exists only for generated fixtures; it is not an access-control boundary. Unknown patient links and unrecognized near duplicates remain possible.
- **Completed result integrity (GL-13):** new evaluations record hashes for output files in the completed ledger, written using an atomic replacement; both report generators verify them. The ledger must be protected separately: hashes in a writable ledger are not signatures and cannot establish authenticity against someone who can change both files and ledger. Historical ledgers lack these hashes; the explicit legacy option reports that limitation instead of fabricating evidence.
- **Demo retention (GL-15):** startup warns about existing session folders without deleting them, and [image handling guidance](../docs/data_privacy.md) explains authorization, storage, crash leftovers and manual review. Synthetic tests cover forced termination and concurrent-looking folders. Encryption, access control, secure erasure and complete removal of library or OS copies are not enforced or guaranteed.
- **Historical provenance (GL-16):** [study provenance](../docs/study-provenance.md) maps recorded source hashes to representative Git snapshots, with the limits of this comparison and the unhashed dependency lock made explicit. Historical artifacts remain unchanged.
- **Annotation metadata (GL-18):** inventory generation validates unique IDs, references, image dimensions, bounding boxes, positive finite area and polygon bounds. It supports the polygon format used by the supplied release and rejects unsupported segmentation formats. This is not an expert review of clinical labels.
- **Inference contract (GL-19, part of GL-22):** new checkpoints record color, orientation, resizing, normalization, class labels and score semantics. Loading rejects mismatches or missing contracts unless the user explicitly acknowledges a legacy checkpoint. Synthetic CPU/GPU score parity is tested when CUDA is available; numerical equality is not guaranteed on all hardware.

## Work that remains

Verified patient mappings, additional independent negative sources, a genuinely external cohort, a prespecified operating requirement, nested model selection and independent calibration are still needed for stronger claims (GL-01–10). Crop/illumination-robust duplicate review, source-balanced experiments, alternative preprocessing, and controlled multi-seed training are future research (GL-08–11). Packages and weights are not hash-locked in a fully portable environment; provenance is not a signed full-environment attestation (GL-17, GL-23). A shared access-controlled cohort registry, logit-space decisions, complete model-contract schema, secure image-retention infrastructure and broad governance controls remain future work (GL-15, GL-19–21, GL-24–26). No new claims of clinical or patient-level validity follow from these software safeguards.

For new studies, follow the [technical guide](../docs/technical-guide.md), retain independently trusted inventory and candidate-pair digests, and use a single protected ledger. The old internal holdout has already been consumed; do not use it to retune a model, cutoff or calibrator.
