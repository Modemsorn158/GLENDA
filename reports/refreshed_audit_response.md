# Response to the refreshed November 2026 audit

The refreshed audit reviewed public source without running the private study. Its baseline corresponds to rewritten repository commit `12f259ef3de5af2351212538bc4020f82c898d3a`; the commit ID changed during the subsequent dataset-image history cleanup. The main scientific limitations remain: the original model missed 55 of 75 annotated positive test frames, unknown patient links prevent a patient-independence claim, only three known groups supplied negative test frames, and no independent external validation has been completed. The consumed test must not be used to choose new models, thresholds or calibration.

## Historical images and subsequent cleanup

On 21 November 2026, the hosting service reported this repository as public. Before the subsequent rewrite, a metadata-only check of one ancestor listed **14,184 image paths** under `data/raw`: 13,438 in the negative-frame directory, 373 in the positive-frame directory and 373 in the annotation directory. This was a count of paths in one historical snapshot; we did not open the images or establish their identifiability, ownership or permissions. The dataset owner and repository custodian should assess the applicable terms, prior access and appropriate response. No breach or legal conclusion is asserted here.

The owner subsequently authorized rewriting the main-branch history to remove dataset image paths. This does not erase earlier clones, forks or caches, and no visibility change, deletion request to the host, notification or claim of complete erasure has been made. The [image-handling guidance](../docs/data_privacy.md) records this limitation.

After the rewrite, a headers-only anonymous request to GitHub for one former image object returned HTTP 200. Therefore, removal from reachable main history did **not** immediately eliminate all public access to the old objects. The owner should ask GitHub Support whether cached/unreachable objects are eligible for removal and consult the data custodian. No image bytes were downloaded by this check.

## Changes in this update

- **Future media checks:** `python scripts/check_tracked_media.py` checks the Git index, and CI runs it on the checked-out commit. It blocks selected media/archive/model extensions, several recognizable file signatures, oversized blobs and changed bytes at the two approved aggregate-figure paths. Tests use synthetic files. This is not a comprehensive privacy scan or protection against altered check code; it does not inspect or remove historical objects. Human review, access controls and custodian approval remain necessary.
- **Inference contract:** version-2 checkpoints fingerprint the actual preprocessing function and validate the model metadata, threshold and single finite output. Missing or mismatched contracts fail by default; the explicit legacy option accepts a missing contract only. A synthetic golden preprocessing/logit test and conditional CPU/GPU score-parity test exercise the path. The function fingerprint does not attest to library versions, all transitive helpers, wheel integrity or hardware, and version-1 contracts without the fingerprint are not silently accepted.
- **Annotation tests:** synthetic cases cover duplicate IDs, invalid references, malformed or out-of-bounds geometry, unsupported segmentation and non-finite area. Schema checks do not establish clinical label accuracy.

The earlier [audit response](comprehensive_audit_response.md) records the grouping, result-hash, inventory and privacy improvements already made. Independent patient-linked cohorts, source-controlled studies, calibration/operating-point design, complete dependency/environment attestation, central ledger governance and an approved real-image retention policy remain open. These tasks cannot be established by rerunning the historical holdout.
